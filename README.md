Замкнутая модель стоимости для небольшой последовательной CNN без BatchNorm.

## 4. Почему так получилось?

### 4.1. FLOPs: почти идеальное совпадение

Причина в том, что FLOPs вычисляются как точное число арифметических операций в заданной архитектуре. Для последовательной CNN без ветвлений и без динамического поведения число операций можно записать в замкнутой форме:

В такой модели нет случайных ветвлений, нет несогласованных оптимизаций. Поэтому теоретический расчёт практически совпадает с реальным измерением на GPU.

### 4.2. Latency: совпадение приблизительное

Для latency использована модель

```python
t = max(compute_time, memory_time) + overhead
```

где `compute_time = flops / F_peak`, а `memory_time = bytes_moved / BW`.

Поэтому масштаб и форма зависимости от `S` и `B` в основном определились верно. Но реальный latency на GPU отличается из-за:

- запуска CUDA kernel с накладными расходами;
- неидеального occupancy и загрузки SM;
- разного поведения при малых/средних/больших батчах;
- накладных расходов на memory allocator и временные буферы;
- кэширования и наличия разных уровней памяти.

Именно поэтому latency совпадает “по порядку величины” и по общей тенденции, но не в точности.

### 4.3. Memory

К сожалению, представленная теоретическая модель представляет собой грубую оценку потребления память. Дополнительно память forward pass на PyTorch включает:

- выходы и промежуточные тензоры после каждого слоя;
- временные буферы, созданные внутри conv / ReLU / pooling;
- выравнивание тензоров и allocator overhead;
- необходимость хранить активации, которые используются внутри слоя или до обратного прохода;
- внутренние служебные структуры CUDA и PyTorch runtime.

В результате формула для memory описывает только основную зависимость от `B * S^2`, но недооценивает дополнительный служебный и allocator-специфичный расход. Поэтому расхождение становится заметным и растёт при больших `B`.

### 4.4. Energy: модель почти не описывает реальность

Так же, как и в случае с memory, формула представляет собой сильную идеализаци.. На реальном GPU энергия зависит не только от количества FLOPs и байт, но и от:

- времени, которое устройство реально проводит в активном состоянии;
- изменения частоты/напряжения и DVFS;
- режима работы памяти и контроллера;
- параллелизма и эффективности ядра.
